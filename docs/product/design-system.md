# Design System ("Passbook")

**[Accepted]** (2026-11-18) The visual language of the web app: direction, tokens, shared components, and the rules that keep financial meaning readable. This document is the canonical home for visual tokens. Product-level UX (navigation, screens, entry flows) is in [user-experience.md](user-experience.md); how the theme is wired into the app is in [frontend-architecture.md](../architecture/frontend-architecture.md#7-ui-composition).

## 1. Direction

Monevo looks like a well-kept **passbook**: a solid ink-navy **cover** (the navigation chrome) around a quiet, cool **paper** page (the content). The cover is the same in both color schemes, so the app is recognisable at a glance; the page follows light or dark.

- Calm and dense enough for numbers, never decorative. Hierarchy comes from type weight, spacing and hairline borders, not shadows or gradients.
- The accent is **ink** (a muted blue). Green and red are **not** brand colors: they are reserved for money flow (inflow and outflow), always paired with a sign or icon ([user-experience.md](user-experience.md#design-direction)).
- **Dashed means planned.** Dashed borders and outlines are used only for planned, scheduled or forecast content and for not-yet-built sections. Actual values are never dashed.
- Original branding: the "M" mark, palette and type choices are Monevo's own.

### Type

- Family: **Hanken Grotesk** (variable, self-hosted from `@fontsource-variable/hanken-grotesk`, upright only, Latin and Latin Extended subsets, precached by the service worker), falling back to the system UI font.
- Its digits are tabular by default; `.mv-figures` also sets `font-variant-numeric: tabular-nums` for amount columns.
- Scale (rem, ratio ~1.2): `xs` 12px, `sm` 13px, `md` 15px (body), `lg` 18px, `xl` 22px. Headings weight 620: h1 24px, h2 20px, h3 17px, h4 15px.

### Shape and elevation

- Radius: `xs` 4, `sm` 6 (default), `md` 8, `lg` 12 (panels and the bottom sheet's top corners), `xl` 16.
- Elevation on the page is a 1px `--mv-border` hairline. Shadows are kept for floating layers only (menus, drawers).

### Focus and motion

- One focus ring: 2px solid, `--mv-focus` on the page and `--mv-cover-focus` on the cover, shown for keyboard focus only.
- `prefers-reduced-motion` disables transitions (Mantine `respectReducedMotion` plus a global rule).

## 3. Layout

- **Desktop (≥ `md`, 62em):** a 240px ink rail with the wordmark, primary destinations, secondary destinations below a divider, the system group (Settings, then Administration for admins) pinned together at the bottom, and the language and color scheme controls in the rail footer.
- **Mobile (< `md`):** an ink top bar (wordmark, language, color scheme) and an ink bottom bar with the four primary destinations plus **More**. More opens a bottom sheet with the remaining destinations, with the system group below a divider. The quick entry button is added with the entry stage, not before ([user-experience.md](user-experience.md#navigation)).
- Page content is capped at 72rem. A "Skip to content" link is the first focusable element and targets `#main-content`.

## 4. Shared components

In [`apps/web/src/components/`](../../apps/web/src/components):

| Component | Purpose |
|---|---|
| `PageHeader` | The page's single `h1` plus an optional description; sets the document title to "Page · Monevo" |
| `StatePanel` | Bordered panel for empty, not-found and error states; `planned` renders it dashed |
| `PlannedBadge` | Dashed pill labelling planned or not-yet-built content |
| `EntityIcon` | An account's or category's icon in a tinted circle of its color (`EntityIcon.tsx`, which also maps the curated `IconKey` set from `@monevo/contracts` to Tabler icons) |
| `IconPicker`, `ColorPicker` | Selection grids for the curated icon set and the color tokens (or a hex color), each option with an accessible name |

Shell pieces live in `apps/web/src/app/` (`AppLayout`, `Wordmark`, `RouteError`, `NotFoundPage`). Styles are plain CSS with `mv-` prefixed class names (`shell.css`, `components.css`).

## 5. Rules

1. Use theme tokens and `--mv-*` variables; no hard-coded colors in components.
2. Green and red only for money flow, and never as the only signal.
3. Dashed styles only for planned, scheduled, forecast or not-yet-built content.
4. Every page has exactly one `h1`, rendered through `PageHeader`.
5. Every user-visible string exists in `en` and `pl`; check that labels fit at 360px in both.
6. Amounts use tabular figures.
7. The operator-configurable accent ([user-experience.md](user-experience.md#design-direction)) will replace the `ink` primary palette; the cover stays ink-navy unless that feature defines otherwise.
